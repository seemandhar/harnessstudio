## What it does

1. **Base decoding.** Every decision is one `ctx.policy.sample(1, sampler=S)` with the original instruction and the raw
   observation. `S` is the sampler the plain `scale` method sends (`hs_scale.decoder:ScaleDecoder`, paper defaults);
   the first action is executed (OpenVLA's native cadence). An episode in which no escalation moves the arm is bitwise
   the plain `scale` method under the same case key (contract, `--case-namespace`, task, episode).
2. **Triggers** (`triggers.py`, public proprio only, ported as code from the SCALE++ replays and checked 400/400
   against them on 200 development episodes): H2 empty close (close commanded, width <= 4 mm within 6 steps, before
   any lifted carry), H1 settled unlifted clamp (close run >= 10 steps, width > 10 mm and settled, rise < 5 mm, not a
   placement or knob twist, the policy now proposes open), optional drop (off). Eligibility: >= 120 steps left;
   re-arm 20 steps after a hand-back; <= 3 escalations; no escalation while a lifted carry is in progress. The same
   function runs online and in the offline replay (`scripts/trigger_replay.py`), so the online first-fire step equals
   the offline prediction on the same trajectory.
3. **Rescue** (`controller.py`; the simulator waits, no env step during planner calls): retain the public packet
   (agentview + wrist RGB, depth, calibration, proprio, step, sha256); call 1 (plan: target + destination pixels,
   open_top, action); geometric witness gate on metric depth (table plane + 1 cm, gripper volume, workspace, object
   extent [1.5, 30] cm / <= 25 cm); call 2 (same-frame marked crop: confirm / wrong_object / abstain); analytic grasp
   (rise, move above with yaw across the short axis, descend with a contact stop to `z_top - min(3.5 cm, h/2)`,
   close 10, lift 6 cm) or, for H1, lift the clamp; measured custody (width > 4 mm, width change > -1.5 mm over 10
   lift steps, rise >= 5 cm); one re-witnessed retry; call 3 (wrist-crop custody confirmation) before an analytic
   place into an open-top destination whose depth column is free (>= 170 steps left at the fire); then hand-back with
   the original instruction. Any abstention, rejection, timeout, transport error or spent budget hands back without
   motion, and then the proposed SCALE action is executed as if nothing happened.
4. **Planner** (`planner.py`): isolated `codex exec` (vendored `vendor/codex_planner.py`, sha256 a37c8f1a...,
   gpt-6.1-sol, read-only sandbox, zero tool items, model id checked every call), strict JSON schemas, <= 12 calls per
   episode, <= 4 per escalation, 180 s per call, run in a worker thread (the harness event loop keeps serving other
   episodes; cancellation kills the codex process group). Each call's trace separates transport status (`timeout`,
   `transport_error`, `parse_error`, `isolation_error`, `budget_refused`) from semantic outcome (`accept`, `abstain`,
   `wrong_object`, `invalid`). Prompts carry the original instruction and a neutral event description only.

## Entry points

| name | role |
|---|---|
| `witnessed-rescue` | candidate |
| `witnessed-rescue-respondoff` | SCALE-shadow null: same triggers, planner and perception calls, responses suppressed; executed actions = SCALE (bitwise plain `scale`) |
| `witnessed-rescue-noplace` | descriptive ablation (grasp + custody, then hand-back) |
| `witnessed-rescue-analytic` | descriptive primitives-only ablation (no hand-back after the first custody); never a Campaign entry |

The Campaign null is the framework's shadow null (`null: shadow`): the controller runs unchanged on the native
trajectory, pays SCALE samples on the shadow session and its planner calls; the executed actions are the baseline's
native (greedy) actions. It controls overhead vs greedy only. In that arm the controller's action log holds the
actions it requested (the framework substitutes the native ones), so its trigger timing approximates the native one.

All parameters are explicit in the cards (`hs_witnessed_rescue/paper*.yaml`, generated by `scripts/make_cards.py`);
effort, place flag, z-close margin and lift are frozen on development data only (review A1/A4/B4).

## Deployment

- Run from a process whose PATH has `codex` and whose user is logged in (`codex login status`). No API key is used.
- Evidence (fix1): retained packets + planner images go to `<hs --out>/witnessed_rescue_evidence/packets/
  <scene>_p<pid>_e<n>/` and the planner call log (hashes, model ids, wall, tokens; never prompt text) to
  `<hs --out>/witnessed_rescue_evidence/planner/planner_calls_p<pid>.jsonl`, unique per process and episode.
  `HS_WR_PACKET_DIR` / `HS_WR_PLANNER_LOG_DIR` are development-only overrides (never set for scored runs); the
  resolved dirs and their source are recorded in `accounting.extra.witnessed_rescue.evidence_dirs`.
- Place free-column check (fix1, review P1): only the 3D gripper + carried-object volume is excluded, and fewer
  than `column_min_points` observed column points means not free (`column_unobserved`).
- `--action-timeout 900` (two consecutive 180 s calls + queueing; >= 600 required by the review).
- Accounting per episode: `accounting.extra.witnessed_rescue` (policy/primitive steps, analytic share, fires,
  escalations with every planner call, custody measurements, places, pause wall time). The last executed step can
  end the episode before the controller counts it; `accounting.steps` is authoritative.

## Disclosure (review C7)

Depth + calibration are harness-only added public sensors; the frozen policy and the SCALE/greedy arms never see
them. The planner is gpt-6.1-sol, unseeded, and may have seen LIBERO in pretraining. Report the analytic-control
share; above 15% of steps on a block the result is a "harness with substantial analytic control". Substitutions vs
Harness VLA: planner from step 0 -> event-triggered; Claude Code/MCP loop -> stateless codex JSON calls; RPent pi0
primitives -> analytic grasp + measured custody; SAM3 -> depth region growing + marked-crop witness.
